# 開発中の試験：ここから始める

<!-- current-version: 1.11.0 -->
対象版は **v1.11.0** です。[取得する版の確認](current-version.md) ／ [試験コース](test-start.md)

今回は**以前の版から更新せず、新しい環境に最初から導入して試験します。**
最初に環境と試す機能を選び、そのコースの番号順に進みます。
各ページを終えたら次のページへ進み、前のページへ戻って続きを探す必要はありません。

## 1. 試験環境を用意する

Ubuntuは、新しいVMか、MyDNSツール導入前の状態を使います。
NASでは今回使うフォルダー・プロジェクト・DSMタスクに以前の設定が残っていないか、先に確認します。
既存のmydns-updaterが運用中なら、新規導入のコピーやプロジェクト作成をその場所へ重ねないでください。
名前が衝突する場合はそこで止め、既存環境の保管・停止と今回の配置先を整理してから始めます。
この資料には、運用中の設定・state・復帰履歴を消す操作はありません。

Ubuntuの準備は[VM構築の参考資料](reference/synology-vm.md)、Dockerを使う場合は続いて[Dockerの導入](reference/ubuntu-docker.md)を行います。
Linux直接実行にはDockerは不要です。

## 2. 試験の違いを確認する

| 試験 | アカウント | 確認すること |
| --- | --- | --- |
| 模擬試験 | 不要 | 用意した正常・異常応答を使い、プログラムの処理を確認する |
| 実アカウントでの基本試験 | 使用 | 実際の通知、設定変更、通知間隔、状態保存を確認する |
| 監視のみの試験 | 設定済みの実アカウント | 処理を一時停止し、異常検知後に手動で再開する |
| 自動復帰の試験 | 設定済みの実アカウント | 処理を一時停止し、定期監視から自動で再起動・復帰することを確認する |

**模擬試験も手元のVMやNASで行います。** 「模擬」と「実機」は反対の意味ではありません。
この資料では、実アカウントを使うかどうかで区別します。CIの成功は、手元の実アカウント試験の代わりにはしません。
実アカウントを使い始める前に、同じアカウントで動く他の環境を停止します。

## 3. コースを1つ選ぶ

監視のみと自動復帰を続けて両方入れる手順ではありません。
両方を検証する場合は、片方を終えて記録を残した後、別の新しい試験環境で次のコースを始めます。
DockerとContainer Managerは基本導入だけで定期ヘルスチェックが動きます。
Linuxは手動ヘルスチェックを標準で使え、定期監視または自動復帰を選んで追加します。

## 試験を終えたら

専用ページの手順で記録を保存し、試験用の更新処理を停止してから、元の運用環境を再開します。
正常終了した試験の後に、履歴のリセットや設定の削除は必要ありません。
通常運用へ進むときは、試験結果を確認したうえで導入します。試験設定を使い続けず、通常の値（CHECK_INTERVAL=300、FORCE_UPDATE_INTERVAL=86400、DEBUG=0）を確認します。

## 既存利用者向けの更新は別の手順

今回の試験コースに、旧版からの更新試験は含めません。
既存利用者向けには[Docker・Synologyの移行手順](image-migration.md)と[Linuxの更新方法](linux.md#更新方法)を残しています。
設定・state・復帰履歴を保持する扱いも変えていません。
